================================================================================
RESUMO DO PROJETO
================================================================================
CasaPy é um servidor Python hospedado em Termux (Redmi10C) que funciona como:
- Interface de gestão de armazenamento remoto (estilo Google Drive)
- Visualizador de informações do sistema (bateria, rede, uptime)
- Sistema de autenticação com usuários isolados
- UI responsiva para desktop/tablet/mobile

================================================================================
STACK TÉCNICO
================================================================================
Framework:      Flask 3.0.3 com Waitress 3.0.0
Linguagem:      Python 3.14.4
Banco Dados:    SQLite (app/data/users.db)
Templating:     Jinja2 3.1.6
Frontend:       HTML5 + CSS3 + Vanilla JavaScript
Networking:     IPv4/IPv6 Dual-stack (host="::")
Autenticação:   HTTP cookies + SHA256 password hashing
Testing:        pytest 9.0.3

================================================================================
ARQUIVOS CRÍTICOS E SUAS RESPONSABILIDADES
================================================================================

app/db.py
- Gerencia conexão SQLite
- Funções: init_db(), get_user_by_username(), create_user(), verify_user()
- Schema: users table (id, username, password_hash, created_at)
- CRÍTICO PARA: Autenticação

app/auth.py
- get_authenticated_user(request) - Extrai e valida cookie de sessão
- Retorna dict com id e username ou levanta HTTPException 401
- CRÍTICO PARA: Proteção de rotas

app/models/user.py
- hash_password(password) - SHA256 hashing
- verify_password(password, hash) - Validação
- Pydantic models: LoginRequest, RegisterRequest
- CRÍTICO PARA: Segurança

app/services/storage.py
- get_user_storage_dir(user_id) - Pasta isolada por usuário
- resolve_storage_path(user_id, relative_path) - Proteção path traversal
- save_upload_file(user_id, path, file) - Upload
- list_storage_files(user_id, path) - Listagem
- storage_summary(user_id) - Estatísticas
- CRÍTICO PARA: Isolamento de dados

app/routes/api/__init__.py
- Todos endpoints passam user_id para storage operations
- Sempre valida autenticação antes de processar
- CRÍTICO PARA: API Security

COMO EXECUTAR
================================================================================

1. AMBIENTE LOCAL (Windows/Linux/Mac):
   python -m venv .venv
   .venv\Scripts\activate  (Windows) ou source .venv/bin/activate (Unix)
   pip install -r requirements.txt
   python -m app.main

2. TERMUX (Redmi10C):
   pkg install python
   git clone <repo-url> ~/CasaPy
   cd ~/CasaPy
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   python -m app.main

3. ACESSAR:
   Local: http://localhost:8000
   IPv4: http://<ip-redmi>:8000
   IPv6: http://[::1]:8000 (local) ou http://[<ipv6-global>]:8000

4. TESTAR:
   python -m pytest tests/ -v

================================================================================
ISSUES RESOLVIDOS ANTERIORMENTE
================================================================================

1. IMPORT PATH ERRORS
   Problema: Rotas usavam 3 níveis ".." em vez de 2
   Solução: Corrigido em home.py, info.py, storage.py, auth/__init__.py
   Lição: Verificar nesting depth ao usar relative imports

2. JINJA2 TEMPLATE RENDERING
   Problema: TypeError com caching de templates
   Solução: Switched from Starlette's Jinja2Templates para direct Environment
   Lição: Direct Jinja2 Environment é mais simples que wrappers

3. DEPRECATED DATETIME
   Problema: DeprecationWarning com datetime.utcnow() em Python 3.14
   Solução: Changed to datetime.now(timezone.utc).isoformat()
   Lição: Always use UTC-aware datetime

4. USER ISOLATION IN STORAGE
   Problema: Old storage.py não tinha isolamento de usuário
   Solução: Rewritten com user_id threading through todas operações
   Lição: User isolation deve ser mandatory desde design inicial

5. INTERFACE STORAGE
   Problema: Interface anterior era confusa (tabela básica)
   Solução: Redesigned para Google Drive style com grid de cards
   Lição: Ícones e navegação visual melhoram UX significativamente

================================================================================
DEBUGGING TIPS
================================================================================

1. VERIFICAR LOGS:
   Console output mostra erros em tempo real
   Check stdout/stderr no terminal do Termux

2. DATABASE ISSUES:
   app/data/users.db é SQLite (use sqlite3 CLI para inspecionar)
   init_db() cria automaticamente na primeira execução

3. PERMISSION ERRORS:
   Storage path: app/storage/user_<id>/
   Certifique que pasta tem permissões corretas no Termux

4. NETWORK ISSUES:
   IPv6 requer configuração do router em alguns casos
   IPv4 é mais confiável para testes iniciais
   Check firewall se conexão recusada de outro device

5. PERFORMANCE:
   Large file uploads podem ser lentos em conexão Termux
   Considerar chunked upload para arquivos > 100MB
